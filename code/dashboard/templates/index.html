      Documentation

      Welcome to the T-60 Analysis Dashboard

      This is the local control room for BasketballElo — a leak-aware, walk-forward NBA spread prediction pipeline. It lets you launch training and backtest jobs, watch them live, and inspect every scorecard the pipeline produces, all from http://127.0.0.1:8765. Nothing leaves your machine.

      How the code evolves

      This lab is not a finished product — it is a living research codebase. New work lands behind tests, leak gates, and the formula bench before it can claim ROI.

      1. Phase 0–1

        Stop the bleeding: P0 correctness fixes and quick wins. Roadmap ↗

      2. Phase 2

        Synthetic formula bench — adversarial invariants, not accuracy tuning. Bench docs ↗

      3. Phase 3+

        Wire unused machinery (Shin, Kelly, Venn-Abers, EPM+minutes), then rating-engine upgrades (Kalman). Project history ↗

      4. Always

        Leak registry stays the source of truth for chronological honesty. Leak registry ↗

      Pipeline stages

      The full suite runs staged phases (0–8) with an anti-overfit review stop. In brief:

      1. Ingest & canonical scores — normalize play-by-play; dual-verify final scores.
      2. Stints — rebuild lineup-vs-lineup possessions from substitutions.
      3. Dates & odds — fail-closed chronology; decision-time vs closing market quotes.
      4. Features at T-60 — everything the model may know 60 minutes before tip, nothing after.
      5. Ratings — player Glicko-2, hierarchical n-man, HAPM ridge, chemistry, lineup & team Elo.
      6. MetaScore stack — past-only out-of-fold stacking into a margin model.
      7. Calibration — three-stage calibration into cover probabilities.
      8. Gates & staking — bet-selection gates and fractional Kelly sizing.
      9. Walk-forward backtest — every season predicted using only earlier data.

      Formula bench

      The synthetic formula test bench feeds adversarial fake data through rating and market formulas. It checks mathematical invariants — not NBA prediction accuracy. A green report means the formulas behave under stress; it does not mean the model beats the market.

      How to interpret the outputs

      MetricWhat it tells you
      Spread / Total MAEAverage absolute error vs actual margins and totals. Lower is better; compare against the market baseline, not zero.
      ATS hit rateShare of graded against-the-spread picks that covered. Only meaningful on the actionable population after gates. Learn more ↗
      ROISimulated return on actionable bets at standard -110 pricing. Small samples swing wildly — check N first. Staking ↗
      Interval coverageHow often actuals land inside the model's prediction interval. Should sit near the nominal level. Calibration ↗
      Brier / LoglossWin-probability sharpness and calibration on the ML tab. Lower is better.
      CLVClosing line value. Positive CLV is the strongest evidence a signal is real — but only when decision ≠ close quotes exist and the claim gate allows it. Leak registry ↗
      Formula bench exitstatusPytest exit code from the last pytest -m bench session (0 = clean). Written to output/bench/latest.json. Bench docs ↗
      xfailA test that is expected to fail until unfinished wiring lands (e.g. Epic 7.x, 5.4, P0.5). Not a crash; unexpected passes fail CI.
      Permutation nullShuffling actual scores should destroy the model’s MAE advantage. If the null looks as good as the real labels, the signal is suspect. Leak registry ↗
      Feature driftLive feature means that deviate from training by a large z-score. Requires saved train/live feature tables for the run; otherwise the panel stays empty on purpose.
